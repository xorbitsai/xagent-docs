A **teammate** is a reusable agent configured for a job. Its instructions define what it does, and its model, skills, tools, and knowledge determine what it can use. In the API and some product dialogs, a teammate is called an **agent**.

## Choose how to run the work

| If you need to | Use |
| --- | --- |
| Handle a one-time request, such as summarizing a file | [New task](/tasks/overview) in the workspace |
| Give a recurring responsibility to a specialist, such as answering product questions | A [teammate](/agents/building) with a saved configuration |
| Delegate work across several specialists | A [Workforce](/workforces/overview) with a manager and worker teammates |

Open **Add a teammate** to browse preconfigured specialists or build your own. For a **Product Support** teammate, connect product documentation, write instructions for the kinds of questions it should handle, and test it in Preview.

## Use a published teammate

Select an available teammate from the workspace or open it from **My Team**. Xagent uses that teammate's configuration for the conversation.

To serve end users, choose an entry point in the teammate's deployment settings. A share link opens a guest chat page. A widget embeds chat on your site. An agent runtime key lets an application call the teammate through the API.

For work that involves several specialties, add an eligible published teammate to a Workforce. The manager can delegate a task to it.
